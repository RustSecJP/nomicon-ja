# 所有権に基づくリソース管理（OBRM）の危険 {#the-perils-of-ownership-based-resource-management-obrm}

OBRM（別名 RAII: Resource Acquisition Is Initialization）は、Rust でたびたび関わることになるものです。標準ライブラリを使うなら、なおさらです。

おおまかに言うと、このパターンは次のとおりです。リソースを獲得するには、それを管理するオブジェクトを作ります。リソースを解放するには、そのオブジェクトを破棄するだけです。すると、オブジェクトがリソースを片付けてくれます。このパターンが管理する「リソース」としていちばんよくあるのは、単なる*メモリ*です。`Box`、`Rc`、そして `std::collections` にあるほぼすべてのものは、メモリを正しく管理できるようにするための便利な道具です。Rust では、これが特に重要です。メモリ管理を任せられる、全体に行き渡った GC が無いからです。それこそが要点でもあります。Rust は制御のための言語です。しかし、対象はメモリだけに限りません。スレッド、ファイル、ソケットなど、ほかのシステムリソースもほぼすべて、この種の API を通して公開されています。
