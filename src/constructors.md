# コンストラクタ {#constructors}

ユーザー定義型のインスタンスを作る方法は、ちょうど 1 つしかありません。型の名前を書いて、そのすべてのフィールドを一度に初期化することです。

```rust
struct Foo {
    a: u8,
    b: u32,
    c: bool,
}

enum Bar {
    X(u32),
    Y(bool),
}

struct Unit;

let foo = Foo { a: 0, b: 1, c: false };
let bar = Bar::X(0);
let empty = Unit;
```

これだけです。型のインスタンスを作るほかの方法はどれも、ごく普通の関数を呼び出しているにすぎません。その関数は何かの処理をして、最終的には「唯一の真のコンストラクタ」に行き着きます。

C++ と違って、Rust には組み込みのコンストラクタがいくつも備わっているわけではありません。コピー、デフォルト、代入、ムーブなどのコンストラクタはありません。理由はさまざまですが、おおむね、*明示的であること*という Rust の考え方に行き着きます。

ムーブコンストラクタは、Rust では意味を持ちません。型が自分のメモリ上の位置を「気にする」ことを認めていないからです。どの型も、メモリのどこか別の場所へ無条件に memcopy されることに備えていなければなりません。つまり、純粋にスタック上にありながらムーブもできる侵入型（intrusive）の連結リストは、Rust では（安全には）実現できません。

代入コンストラクタとコピーコンストラクタも、同じように存在しません。Rust にある意味論はムーブの意味論だけだからです。`x = y` は、せいぜい y のビットを変数 x にムーブするだけです。Rust は、C++ のコピー指向の意味論を実現する仕組みを 2 つ用意しています。`Copy` と `Clone` です。Clone は、コピーコンストラクタに実質的に相当するものですが、暗黙のうちに呼び出されることは決してありません。クローンしたい要素に対して、`clone` を明示的に呼び出さなければなりません。Copy は Clone の特殊な場合で、その実装が単に「ビットをコピーする」だけのものです。Copy の型は、ムーブされるたびに暗黙のうちにクローン*されます*。しかし Copy の定義から、これは古いコピーを未初期化として扱わないというだけのことで、何もしない操作（no-op）です。

Rust には、デフォルトコンストラクタに実質的に相当するものを指定するための `Default` トレイトがありますが、このトレイトが使われることは非常にまれです。変数が[暗黙のうちに初期化されない][uninit]からです。Default が役に立つのは、基本的にジェネリックプログラミングだけです。具体的な文脈では、型は、何らかの「デフォルト」のコンストラクタとして静的な `new` メソッドを用意します。これはほかの言語の `new` とは関係がなく、特別な意味もありません。ただの命名の慣習です。
