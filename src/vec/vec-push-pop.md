# push と pop {#push-and-pop}

よし。初期化はできます。割り当てもできます。では、実際に何か機能を実装しましょう。まずは `push` からです。必要なのは、満杯かどうかを検査して満杯なら伸長し、次の添字へ無条件に書き込み、そして長さを 1 増やすことだけです。

書き込みを行うときは、書き込み先のメモリを評価しないよう注意しなければなりません。最悪の場合、そこはアロケータから来た本当に未初期化のメモリです。良くても、以前 pop した古い値のビット列です。いずれにせよ、そのメモリを添字で指して参照外しするわけにはいきません。それは、そのメモリを T の有効なインスタンスとして評価することになるからです。さらに悪いことに、`foo[idx] = x` は `foo[idx]` の古い値に対して `drop` を呼び出そうとします。

これを行う正しい方法は `ptr::write` です。これは、対象のアドレスを、渡した値のビット列でやみくもに上書きするだけです。評価は一切伴いません。

`push` では、（push が呼ばれる前の）古い len が 0 であれば、0 番目の添字に書き込みたいわけです。したがって、古い len だけオフセットすべきです。

<!-- ignore: simplified code -->
```rust,ignore
pub fn push(&mut self, elem: T) {
    if self.len == self.cap { self.grow(); }

    unsafe {
        ptr::write(self.ptr.as_ptr().add(self.len), elem);
    }

    // Can't fail, we'll OOM first.
    self.len += 1;
}
```

簡単ですね。`pop` はどうでしょうか。今度はアクセスしたい添字は初期化済みですが、Rust は、値をムーブで取り出すためにそのメモリ位置を参照外しすることを、そのままでは許してくれません。そうするとメモリが未初期化のまま残ってしまうからです。ここで必要なのは `ptr::read` です。これは、対象のアドレスからビット列をコピーして取り出し、それを T 型の値として解釈するだけです。これにより、そのアドレスのメモリは、実際にはまったく問題の無い T のインスタンスがそこにあるにもかかわらず、論理的には未初期化になります。

`pop` では、たとえば古い len が 1 であれば、0 番目の添字から読み出したいわけです。したがって、新しい len だけオフセットすべきです。

<!-- ignore: simplified code -->
```rust,ignore
pub fn pop(&mut self) -> Option<T> {
    if self.len == 0 {
        None
    } else {
        self.len -= 1;
        unsafe {
            Some(ptr::read(self.ptr.as_ptr().add(self.len)))
        }
    }
}
```
